DeepSeek, 자체 검색엔진 기반 Search·Fetch API 전면 개방 — 성공 요청 1,000건당 $0.75, 11/1 과금 시작

2026-10-17 · 원문 이슈 #3335

10월 17일, DeepSeek이 공식 X 계정(@deepseek_ai) 스레드와 API 문서를 통해 Search API와 Fetch API를 모든 개발자에게 개방했다. 핵심은 이 문구 한 줄이다: "powered by DeepSeek's in-house search engine". 자체 검색엔진 — 전 세계에서 하루 수억 건의 요청을 처리하고 있다는 것이 DeepSeek의 주장이다.

개발자 관점 한 줄 요약: 에이전트에 웹 검색 레이어를 붙일 때 DeepSeek API 키 하나로 모델+검색을 해결할 수 있는 옵션이 생겼다. Search는 쿼리→구조화 웹페이지 결과, Fetch는 단일 URL→Markdown. 과금은 성공 요청 1,000건당 $0.75, 실패·빈 결과·타임아웃은 과금 안 됨. 서버사이드 도구(DeepSeek Harness·Claude Code·Codex) 경유 호출은 11/1까지 무료이니 지금 붙여보고 콜 볼륨을 계측해두는 게 유리하다.

핵심 사실

  • 2026-10-17 발표 — 공식 X 스레드(@deepseek_ai, 08:35 UTC) + 공식 API 문서("17 October 2026"). (DeepSeek 공식 X·API 문서, FourWeekMBA 10/17)
  • Search API — 쿼리에 대한 웹페이지를 찾아 구조화 결과를 반환. Fetch API — 단일 웹페이지의 콘텐츠를 Markdown으로 반환. (공식 API 문서)
  • 가격: 각 엔드포인트 성공 요청 1,000건당 $0.75. HTTP 200을 반환하고 결과가 있을 때만 과금 — 실패 요청·빈 검색 결과·타임아웃은 과금되지 않고, 반환 결과 수와 무관하게 동일 요금. (공식 API 문서, FourWeekMBA)
  • 레이트 리밋: 계정당 각 엔드포인트 초당 5요청 (Search 5·Fetch 5, 별도 집계). (공식 API 문서)
  • 무료 구간: DeepSeek Harness·Claude Code·Codex의 서버사이드 도구 호출은 현재 무료. 과금은 2026-11-01 00:00 베이징 시간(10/31 16:00 UTC)부터. 문서 원문: "These calls are currently free of charge; per-request billing starts at 00:00 Beijing time on November 1, 2026." (공식 API 문서)
  • 패키지 발표: 같은 X 스레드(1/4)에서는 V4.1-Flash-1017 모델 업데이트도 함께 발표 — 웨이트 MIT 공개 (모델은 이슈 #3327로 별도 이슈화).

두 엔드포인트의 역할 분담

역할 분담이 깔끔하다. Search는 "어디에 답이 있는지"를 찾는 단계 — 쿼리를 던지면 웹페이지를 찾아 구조화된 결과로 반환한다. Fetch는 "그 페이지에 뭐가 있는지"를 읽는 단계 — 단일 URL을 주면 페이지 콘텐츠를 Markdown으로 뽑아준다. 에이전트의 리트리벌 파이프라인(검색→선별→읽기→인용)을 두 개의 API 호출로 그대로 구현할 수 있다.

가격 구조: 성공 건에만 과금

과금 기준이 에이전트 워크로드에 유리하게 설계돼 있다. 성공 요청 1,000건당 $0.75 — 즉 검색 1회당 $0.00075. 실패 요청, 빈 검색 결과, 타임아웃은 과금되지 않는다. 검색 결과가 1개든 10개든 요금은 동일하다. 에이전트가 "검색 실패 → 재시도"를 반복해도 실패분은 공짜라는 뜻이다.

계정당 각 엔드포인트 초당 5요청 제한은 별도 집계(Search 5 + Fetch 5). 병렬 에이전트를 여럿 돌리는 환경에서는 이 수치를 기준으로 동시성을 설계해야 한다.

무료 vs 유료: 배선 방식에 따라 갈린다

가장 주의할 포인트다. 무료 기간은 서버사이드 도구(DeepSeek Harness·Claude Code·Codex) 경유 호출에만 적용된다. 엔드포인트를 직접 호출하면 즉시 $0.75/1k 과금이 시작된다. 같은 검색이라도 에이전트의 배선 방식에 따라 무료/유료가 갈린다는 뜻 — 과금 시작 전인 지금 붙일 때는 이 분기를 코드에 명시해두는 편이 안전하다.

// 사용 패턴 스케치 (실제 엔드포인트·파라미터는 공식 문서 참조)
// https://api-docs.deepseek.com/guides/search

// 1) Search: 쿼리 -> 구조화 웹페이지 결과
//    실패·빈 결과·타임아웃은 과금 안 됨 -> 재시도 로직을 아낌없이
results = search(query="DeepSeek V4.1-Flash 1017 changelog")

// 2) Fetch: 유망한 URL -> Markdown 본문
//    반환 결과 수와 무관하게 동일 요금 -> 넉넉하게 읽어도 됨
doc = fetch(url=results[0].url)

// 3) 동시성: 엔드포인트별 5 QPS (Search 5 + Fetch 5, 별도 집계)
//    병렬 에이전트 환경에서는 이 수치 기준으로 스로틀링 설계

배경·맥락

DeepSeek은 9월 V4.1-Flash 출시 이후 모델 가격 경쟁을 주도해 왔다. 이번에는 모델이 아니라 "에이전트가 호출하는 도구" 자체를 상품화한 것으로, 모델 + 검색 레이어를 하나의 API 키 뒤에 묶어 에이전트 워크로드용 검색 API 시장(전용 검색 API 업체)과 직접 경쟁 구도를 만든다. 모델 체크포인트 업데이트와 같은 날·같은 스레드로 발표된 패키지다.

주의 (미확인·쟁점): 검색엔진의 인덱스 규모·랭킹 품질에 대한 독립적인 정확도 평가는 없다. 무료 기간 중 서버사이드 호출의 볼륨 제한·남용 방지 정책은 문서에 명시되지 않았다. "하루 수억 건 처리" 같은 처리량·벤치마크 수치는 DeepSeek 자체 주장이며 독립 재현이 없다.

AX TF 관점: 검색 API 과금의 기준점($0.75/1k, 5 QPS)이 공개된 만큼 에이전트형 기능의 리트리벌 비용 구조를 가늠하기 쉬워졌다. 검색 1회당 $0.00075 — 모델 토큰 비용과 합산해도 에이전트 한 태스크의 웹 리서치 비용이 센트 단위로 계산된다. 11/1 과금 시작 전까지 무료 구간이 있으니, 지금 붙여보고 콜 볼륨을 계측해두면 이후 비용 예측의 기준선이 된다.
