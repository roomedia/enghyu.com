alchaincyf 'huashu-motion' — 코딩 에이전트가 한 마디로 상업급 제품 런칭 영상 생성·작곡·화면 지점 수정

2026-10-21 · 원문 이슈 #3339 · 소스: GitHub (10/18)

alchaincyf(花叔)가 10월 18일 GitHub에 공개한 코딩 에이전트용 스킬 huashu-motion의 약속은 한 줄이다: "一键直出商业级产品宣传片"(클릭 한 번에 상업급 제품 홍보 영상 완성). Claude Code·Codex 같은 코딩 에이전트에게 제품 30초짜리 런칭 영상을 부탁하면, 에이전트가 제품을 읽고 세 가지 방향을 제안한 뒤 영상 전체를 쓰고 직접 작곡까지 한다. 그리고 브라우저 편집기에서 화면을 찍어가며 수정한다. 설치는 한 줄:

npx skills add alchaincyf/huashu-motion

Agent Skills 표준 배지를 달아 Claude Code·Codex·WorkBuddy·Grok Bot·Muse·Dots 런타임에서 동작하고, 라이선스는 MIT. 공개 약 6시간 만에 스타 204개(약 시간당 35개, 일 환산 약 840개)를 모았다.

작곡가 모드: 악보를 먼저 쓰고, 박자에 맞춰 컷 전환

가장 재밌는 아이디어는 음악을 LLM이 텍스트로 작곡한다는 점이다. 에이전트는 리듬 시트에 맞춰 순수 텍스트인 ABC 기보법으로 악보를 먼저 쓰고, 장면 마커를 박자에 정렬한 뒤 피아노·현악·드럼 샘플로 연주한다. 영상 생성 모델을 부르는 게 아니라, 모든 소리가 로컬에서 생성된다 — 유료 API 호출이 없다. 음악 모델(Suno·Udio 같은)을 쓰는 게 아니라 악보를 코드로 쓰고 샘플로 연주한다는 발상이 코딩 에이전트와 기막히게 맞는다: 텍스트만 잘 다루면 되니까.

작곡이 싫으면 내장 12개 제품 카테고리 × 3종 배킹트랙 중에 시드 기반으로 뽑아 쓸 수 있고, 악기 샘플은 om samples build 한 번이면 진짜 악기(CC0·CC-BY 오픈 샘플, 약 55MB)를 내려받는다. 객체가 화면에 떨어지는 프레임에는 23종 효과음(착지·타이핑·글리치 등)이 자동 배치된다.

화면 지점 수정(point-to-edit): 고치고 싶은 곳을 찍는다

편집 루프가 두 번째 킬러 기능이다. 편집기(om studio)에서 C를 누르고 화면을 클릭한 뒤 수정 내용을 적으면, 에이전트는 코멘트와 함께 타임코드·씬·클릭한 요소와 소스 내 위치를 받고, 해당 프레임과 클릭 영역을 스크린샷으로 확대 확인한 뒤 그 부분만 수정한다. 모든 버전은 보관되고 ⌘Z로 롤백. 제목·숫자·색상·체류 시간 같은 건 편집기 우측 입력창에서 직접 바꾸면 되니 에이전트를 기다릴 필요도 없다.

이 패턴은 Claude Motion(10/8 공개, Team·Enterprise 한정 베타)의 "화면을 가리켜 수정" 기능과 정확히 같은 문법이다. 차이점: 이건 스킬 한 줄로 공개됐고, MIT라 누구나 가져다 쓸 수 있다.

기술 구조: 한 편의 영상 = 하나의 index.html

핵심 아키텍처는 전작 huashu-art-motion(#3231)과 같은 철학이다. 영상 생성 모델을 호출하지 않고 GSAP·Canvas·Three.js·SVG로 화면을 코드로 그린다. 한 편의 영화는 하나의 index.html이고, 모든 프레임은 코드와 시간으로만 결정된다:

에이전트 ──작성──▶ my-film/index.html ◀──감시── om studio (브라우저 편집기)
      ▲                                          │
      └── om inbox --wait ◀── .om/inbox.jsonl ◀── 화면 클릭 + 한 줄 코멘트

기술적 디테일 몇 가지:

  • 감독 규칙, 템플릿 아님: 실제 런칭 영상 21편(Apple·Nothing·GoPro·Google·Vercel·Linear·Anthropic 등)을 FFmpeg로 절단점·비트·라우드니스·에너지 곡선까지 측정하고, 고관여 영상 142편을 분해해 20종 모션 언어를 정리했다. "3초 안에 훅, 중반에 한 번 폭발, 가장 큰 소리 전엔 한 박자 쉰다" 같은 규칙이 스킬에 내장.
  • 렌더는 네 PC의 Chrome: CPU 코어 수만큼 브라우저를 병렬로 띄워 렌더(기본 최대 8개). 30초 영상이 14코어 Mac에서 약 12~15초 만에 렌더되고, 모션 블러 포함이면 1~1.5분.
  • QA가 내장: om check(렌더 전 스크립트·규칙 위반·잘린 자막 검사), om qa(완성본의 단발성 프레임·빈 구간·하드컷 검사). 스킬이 에이전트에게 "정말 프레임을 보고, 정상 속도로 한 번 봐라"고 요구한다.
  • 학습 루프: 작업 시작 전 과거 편호와 실수를 읽고, 끝난 후 편집기 코멘트를 흡수해 로컬에만 저장.

저자의 실측 데모: DeepSeek V4.1 Flash(1017)로 22초 모션 영상을 3차례 피드백·30분 이내에 제작, 비용 1.95元(元), 캐시 적중률 99.4%. "비싼 모델 없이도 된다"는 주장의 근거다.

AX TF 관점: '에이전트 제작 파이프라인' 패턴의 구체적 구현체다. 음악·영상 생성을 API 비용이 드는 블랙박스에 맡기는 대신 텍스트 악보→로컬 샘플, 화면→코드 렌더로 전부 로컬화했다는 점이 프로모션 에셋 자동화(릴스·프로덕트 헌트 영상·온보딩 클립)에 바로 응용 가능하다. 특히 point-to-edit의 "클릭 좌표+소스 위치를 함께 코멘트로 넘기는" 인터페이스는 이미지·UI 리뷰 워크플로우에도 이식할 만한 아이디어다.

주의 (미확인·쟁점): 영상 품질·작곡 수준에 대한 주장은 저자의 데모 GIF 기준이며 제3자 검증이 없다. 1.95元·99.4% 캐시 적중률도 단일 실행 실측치. README는 중국어 원본이며 영문판(README.en.md)이 별도 존재한다. 그리고 솔직한 한계도 명시돼 있다: 에이전트는 귀가 없다(스펙트럼으로 검사, 최종 청취는 사람), 실사·실제 사람은 못 만든다(코드 렌더만), 효과는 모델 취향에 좌우된다.

배경·맥락

같은 저자의 전작 'huashu-art-motion'(#3231)은 코딩 에이전트가 코드로 그리는 아트 애니메이션 스킬이었다. huashu-motion은 그 다음 단계로 작곡·편집 루프까지 얹은 상업용 런칭 영상 파이프라인이다. 저자 배경도 독특하다 — '小猫补光灯'(고양이 조명) 앱으로 AppStore 유료 차트 1위를 찍은 독립 개발자. 10/8 Anthropic의 Claude Motion 발표를 보고 "우리 스킬이 Motion을 완벽히 재현하고 훨씬 강하게"라는 한 줄 지시로 Claude Code에게 만들게 한 게 시작점이다. 첫날 만든 건 "자기가 거짓말 안 했다는 걸 증명하는 공학"이었다고 — 그날 바로 갈아엎고, '안 멋지다·지루하다·폰트가 구리다'는 피드백을 전부 규칙으로 돌려썼다. 그게 이 스킬의 감독 규칙이 된 셈이다.
