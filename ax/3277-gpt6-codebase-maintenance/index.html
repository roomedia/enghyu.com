OpenAI의 'GPT-6 family로 소프트웨어 유지보수' — 죽은 코드·기능 스위치·CI 최적화 실전 프롬프트

2026-10-15 · 원문 이슈 #3277

OpenAI Developers 블로그가 2026-10-14에 "Maintaining software with the GPT-6 family"를 게시했다. 저자는 OpenAI Core Experimentation 팀의 Rodrigo Roim. GPT-6 계열(Codex + GPT-6 Astra, GPT-6.1 Sol)을 이용한 코드베이스 유지보수의 실전 기록이다.

핵심 수치: 팀은 GPT-6 제안으로 시작된 유지보수 풀 리퀘스트 1,400건 이상을 병합했다. 다루는 영역은 세 가지다 — 죽은 코드 제거("Removing unused code"), 오래된 실험·기능 플래그 추적("Tracking down stale experiments"), CI 비용·런타임 절감("Reducing cost and runtime of continuous integration").

1,400+GPT-6 제안으로 시작된 병합 정리 PR
80만 줄+삭제된 코드 (X 요약 기준)
48%특정 서비스 컨테이너 이미지 축소 (X 요약 기준)
3개 영역죽은 코드 · 기능 플래그 · CI 최적화

이 글의 진짜 재미는 블로그 본문보다 X에서 시작됐다. @CopperForgeAI가 10/15에 이 글을 소개하며 실제로 사용된 프롬프트들을 공개했고 (조회수 2.6만, 북마크 651), 그 프롬프트들의 설계 철학이 명확하게 드러나기 때문이다: 모델에게 "확인하라"는 권한을 넓게 주고(Slack·Statsig·프로덕션 데이터까지 스스로 뒤지게), "삭제 근거를 PR에 명시"하게 하는 식으로 신뢰를 확보한다. 아래 프롬프트 인용은 이 이슈의 중국어 번역본 기준이다.

1. 죽은 코드 정리: "증거를 찾은 뒤에만 삭제"

첫 번째 프롬프트의 요지는 한 줄이다: 저장소의 쓸모없는 코드를 찾아 정리하라. Slack, Statsig(기능 스위치 플랫폼), 필요한 모든 소스를 자유롭게 확인해 코드가 실제로 사용되지 않음을 확인하라.

# 프롬프트 1 — 죽은 코드 정리 (의역)
"저장소에서 사용되지 않는 코드를 찾아 정리하라.
Slack과 Statsig(기능 스위치 플랫폼)을 포함해 필요한 모든 소스를
자유롭게 확인하고, 코드가 실제로 사용되지 않음을 확인한 뒤에만
PR에 삭제 근거를 나열하라."

개발자 관점에서 중요한 건 이 프롬프트가 grep 수준의 참조 검색이 아니라 조직의 전체 신호를 모델에게 열어준다는 점이다. GPT-6 Astra는 Slack 논의, Statsig 실험 설정, 프로덕션 프로파일링 데이터까지 스스로 뒤지고, 프로덕션 호출이 0임을 확인한 뒤에만 PR에 삭제 근거를 나열한다. "이 함수는 왜 지웠나?"라는 리뷰 질문에 모델이 먼저 답할 수 있는 구조다.

2. 오래된 실험·기능 스위치 정리: /goal 패턴

두 번째 프롬프트는 /goal 스타일의 장문 명령이다. 전체 저장소에서 오래되고 상수화·폐기·전량 롤아웃된 Statsig 스위치·설정·실험을 찾아, 프로덕션 동작을 바꾸지 않고 안전하게 제거하라. 열거·상수·래퍼 함수·별칭·동적 조립 이름으로 간접 참조까지 찾고, 프로덕션 텔레메트리·프로파일링으로 CPU 오버헤드를 평가해 비싼 무용 지름길(expensive no-op)을 찾는다. 결과물은 소유자·파일 워크플로우별로 그룹핑한 Markdown 리포트로, 병렬 처리용이다.

이 패턴은 Series 코드베이스 같은 곳에 바로 적용 가능하다. "feature flag를 끄는 게 아니라 지우는" 작업을 모델이 스스로 리포트로 쪼개주니, 사람이 해야 할 일은 소유자에게 할당하는 것뿐이다.

3. CI 최적화 + 에이전트 규칙 자가검증

세 번째 프롬프트는 두 파트다. CI 부하 절감 아이디어를 표로 정리하고, 저장소의 과거 실행 기록을 기준으로 일일 예상 절감 CI 분(min) 순으로 정렬하라. 불안정 테스트는 최근 CI 기록을 보고 고쳐 PR한다.

그리고 가장 흥미로운 파트 — AGENTS.md 규칙 자가검증. 최근 Codex 세션을 뒤져 에이전트를 오도한 지침을 찾고, 같은 스냅샷·모델에서 지침 유지 vs 수정 버전으로 두 번 리플레이해 작업 품질·도구 호출·토큰 비용을 비교한다. 에이전트 코딩 워크플로우의 메타 최적화: 규칙 자체를 에이전트가 실험으로 검증하는 것이다.

# 프롬프트 3 — CI + 자가검증 (의역)
"본 저장소의 CI 부하를 줄일 아이디어를 표로 정리하고,
저장소의 과거 실행 기록을 기준으로 일일 예상 절감 CI 분(min)
순으로 정렬하라. 불안정 테스트는 최근 CI 기록을 보고 고쳐 PR.
AGENTS.md 규칙은 최근 Codex 세션을 뒤져 에이전트를 오도한
지침을 찾아, 같은 스냅샷·모델에서 유지/수정 버전으로
두 번 리플레이해 품질·도구 호출·토큰 비용을 비교하라."

아직 안 밝혀진 것. "80만 줄 삭제·컨테이너 이미지 48% 축소" 수치는 X 포스트 요약에만 있고, 블로그 본문에서의 정확한 표현은 이번 조사에서 확인하지 않았다. 프롬프트 전문은 중국어 번역본 기준이며, 영문 원문 대조는 하지 않았다.

실무 관점: Series에 그대로 써먹을 만한 것

  • 확인 권한을 프롬프트에 박기: "grep으로 참조 검색"이 아니라 "Slack·Statsig·프로덕션 호출을 뒤져 실제 미사용을 증명"하는 게 죽은 코드 정리의 핵심이다. Series에도 Slack·프로덕션 신호를 연결하는 패턴으로 옮겨 쓸 수 있다.
  • 삭제 근거를 PR에 강제: "왜 지웠나"를 모델이 먼저 적게 하면 리뷰 비용이 떨어진다. 유지보수 PR 템플릿에 "삭제 근거" 항목을 넣는 것만으로 흉내 낼 수 있다.
  • CI 아이디어를 분(min) 단위로 정렬: 감(感)이 아니라 수치로 우선순위를 세운다. 우리 레포 CI 히스토리만 있으면 같은 프롬프트를 돌릴 수 있다.
  • AGENTS.md 자가검증: 에이전트 워크플로우 규칙을 "리플레이 실험"으로 검증하는 패턴은 규칙 품질 관리의 재사용 가능한 템플릿이다.
