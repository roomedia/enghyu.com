Asymptote Labs 'Beacon' — 29개 하네스를 가로지르는 에이전트 메모리 레이어, Jev 평가 연동 (10/21, GitHub)

2026-10-21 GitHub 공개 · ax-trend 이슈 #3384 · Beacon

핵심 — 한 에이전트의 교훈을 다른 에이전트가 쓴다

  • Asymptote Labs가 오픈소스 에이전트 메모리 레이어 Beacon을 GitHub에 공개하고 있다 (Asymptote-Labs/agent-beacon, MIT 라이선스).
  • 지원 로컬 런타임은 README 표 기준 29개다. Claude Code, Codex CLI/Desktop, Cursor, OpenCode, Hermes Agent, Gemini CLI, goose 등이 들어간다.
  • 레포 지표 (2026-10-21 조회): 스타 2,322, 포크 208, 생성 2026-05-12, 릴리스 159건 (최신 v1.3.45, 2026-10-20), PR 909건.
  • Avi Chawla가 X에서 Beacon으로 세션을 모으고 Jev로 평가하는 워크플로우를 소개했다 (2026-10-21, 조회 4,450).

캡처 — 세션을 상시 기록해 공통 이벤트로

  • 코딩 에이전트 하네스의 세션을 hooks·OTLP·폴링으로 상시 캡처한다.
  • 캡처한 기록은 OpenTelemetry 기반 공통 이벤트 형식으로 정규화한다.
  • 원본 기록은 로컬 JSONL(~/.beacon)에, 학습 산출물은 프로젝트별 로컬 memory.db에 저장한다 (README·docs).

승격 — 사람 리뷰를 통과한 것만 재사용

  • 캡처한 기록에서 재사용할 지식을 뽑는 승격은 사람 리뷰·승인을 거친다 (docs: "deliberately review-gated").
  • 재사용 경로는 두 가지다. 로컬 MCP 서버의 search_memory 같은 도구, 그리고 승인된 메모리를 Agent Skill로 설치하는 방식이다.
  • 트레이스 평가자로 TypeSafe의 Jev(System One)를 외부 연동한다. 가린(redacted) 트레이스를 보내면 유형화된 질문에 확률만 돌려받는다.
  • 승격 기준은 docs에 명시돼 있다. 성공 확률 0.50 이상, 3개 확률 평균 0.60 이상이다.
  • Jev는 Asymptote 제품이 아니라 별도 회사의 유료 API다. 이 점은 헷갈리기 쉬우니 구분해 둘 필요가 있다.
캡처(Beacon)와 평가(Jev)를 나눈 구조가 핵심이다. 각 층을 갈아끼울 수 있다. 하네스가 여럿인 운영 환경에서 직접 시험해 볼 만한 형태다.

아직 안 밝혀진 것 / 쟁점

  • 효과 수치 없음: 메모리 재사용이 에이전트 성공률을 얼마나 올리는지, 레포 안에 벤치마크·사례가 없다. 핵심 주장은 아직 미검증이다.
  • 로컬 우선과의 긴장: 기본 캡처는 로컬이지만 설치 마법사는 Beacon Cloud를 기본값으로 제시하고 Local은 opt-out이다.
  • 보안 이슈가 열려 있다: 비밀정보 가림(redaction) 적용, 세션 로그 접근 제한, 패키지 서명 요구 같은 이슈가 미해결 상태다.
  • 기여자 커밋에 에이전트 계정(claude 856커밋) 비중이 커서, 코드 품질의 독립 검증은 없다.

왜 중요한지 — 관측에서 학습으로 넘어가는 부품

Jev는 이 트래커에서 여러 번 다룬 결정 모델이다 (#3336 등). Beacon은 그 Jev를 단독 도구가 아니라 "캡처 레이어의 평가 부품"으로 붙인 사례다. 에이전트 실행 기록을 관측(observability)에서 학습으로 넘기려는 시도가 부품 단위로 나뉘어 조립되기 시작했다. 여러 코딩 에이전트를 함께 쓰는 실무에서 "한 에이전트가 겪은 교훈을 다른 에이전트가 재사용"하는 층이 표준 부품이 될 수 있다.
