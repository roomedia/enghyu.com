2026-10-22 · AX 트렌드 · 원문 이슈 #3346

2026-10-18 릴리스 노트에 따르면, fork 서브에이전트(subagent_type: "fork")가 claude -p·Agent SDK·데스크톱 앱·VS Code에서 기본 활성화됐다. 터미널은 이미 기본값이었고, 이번에 전 서피스로 확대된 것이다. 병렬 작업을 많이 돌리는 사람에게는 기본값 변경이므로 확인이 필요하다.

fork 서브에이전트 = 독립 컨텍스트에서 도는 병렬 워커. 메인 대화의 컨텍스트를 오염시키지 않고 작업을 나눠 처리하는 구조다. 이 릴리스부터 4개 서피스에서 꺼져 있는 옵션이 아니라 켜져 있는 기본값이다.

이번 릴리스에서 바뀐 것

  • fork 기본 활성화: claude -p / Agent SDK / 데스크톱 / VS Code.
  • 실행 규칙 변경: 데스크톱·VS Code는 메인 대화의 서브에이전트를 항상 백그라운드로 실행한다. 반대로 서브에이전트 자신의 Agent 호출은 claude -p·Agent SDK·데스크톱·VS Code에서 기본 포그라운드 실행으로 바뀐다.
  • 새 환경변수 CLAUDE_CODE_AUTO_MODE_MODEL — 클라이언트 측 auto mode 분류기가 쓸 모델을 고르는 용도. 서버 측 auto mode 모델은 변경 없음.
  • 훅 스로틀링: "at most 12 of one event run at a time; the rest wait their turn" — 이벤트당 최대 12개 훅만 동시 실행하고 나머지는 대기한다.
  • Read 도구 수정: 어떤 크기 이미지든 메모리에 전부 읽던 문제 수정 — 128MB 초과 이미지 소스는 거부한다.
  • /config에 Idle compaction 행 추가 — idle compaction을 끄고 켤 수 있고, compaction 후 안내에 끄는 방법이 표시된다.
  • 플러그인 다수 켠 상태 시작 시간 개선. 권한 모드 미지정 시 claude -p·SDK 세션이 third-party provider에서 default 모드로 시작한다.

설정 플래그 — 켜기·끄기

# fork 서브에이전트 끄기
export CLAUDE_CODE_FORK_SUBAGENT=0

# auto mode 분류기 모델 지정 (클라이언트 측)
export CLAUDE_CODE_AUTO_MODE_MODEL=<model>
⚠️ 예외 하나: "claude mcp serve never offers them" — claude mcp serve에서는 fork 서브에이전트를 제공하지 않는다. MCP 서버 경로로 도는 환경이라면 fork 동작을 기대하지 말 것.

왜 중요한지

fork가 기본값이 된다는 것은 서브에이전트 병렬 실행이 이제 옵트인(opt-in)이 아니라 옵트아웃(opt-out)이라는 뜻이다. 에이전트 워크플로를 돌리는 팀이라면 비용·동시 실행 수를 다시 볼 필요가 있다. 훅 스로틀링(12개)은 그 완충 장치로 보인다.

Claude Design의 12월 14일 종료 예고는 별도로 주목할 일정이다. standalone 디자이너 도구를 쓰고 있었다면 마이그레이션 계획을 세워야 한다. 관련 이슈: #3329 (첫 토큰 지연 4.07초→1.33초), #3337 (Claude가 Claude Code 코드 90% 작성 중).
