pstack — 에이전트용 엄격 엔지니어링 스킬 모음, Cursor 공식 플러그인 등록

2026-10-16 · 원문 이슈 #3293

lauren(@poteto, 인증 계정)이 2026-10-16 X에 자신의 에이전트용 엔지니어링 스킬 모음 pstack을 홍보했다. "try pstack!"으로 시작하는 그 글은 이렇게 말한다 — "it's my personal set of skills for rigorous and autonomous engineering with agents" (에이전트와 함께 엄격하고 자율적으로 엔지니어링하기 위한 나만의 스킬 세트). 조회수 20.1만, 좋아요 3.7천, 북마크 4.1천. Laravel 창시자 Taylor Otwell이 인용하며 "pstack is the new solid"이라 평가했다.

본인도 밝혔듯 pstack은 lauren이 개인적으로 쓰던 스킬 세트였다. 이제 cursor/plugins 공식 레포의 플러그인으로 등록됐다. 공식 설명: "if you want to go fast, go deep first. pstack helps you write less, but higher quality code. rigorous agent workflows you can parallelize with confidence." — 빨리 가고 싶으면 먼저 깊이 파고들어라. 적게 쓰되, 더 좋은 코드를.

누가 만들었나

lauren 본인 소개에 따르면 그는 Meta·Netflix·Cursor를 거쳤고, React core team(React Compiler) 소속이다. pstack은 "AI가 슬롭(slops) 코드를 너무 많이 쓴다"는 문제의식에 대한 그의 답이다. 단순히 프롬프트를 잘 짜는 팁 모음이 아니라, 에이전트가 독단적으로 추측하지 않고 증거에 기반해 작업하도록 강제하는 워크플로우 스킬이라는 점이 핵심이다.

왜 주목할 만한가: #3133에서 다룬 cursor/plugins 공식 레포에 등록된 개별 플러그인이라는 점. 그리고 #3273의 tester-army의 /create-verification-skill이 "Based on @poteto skills"라고 명시했듯, poteto의 스킬 방법론은 이미 에이전트 스킬 생태계의 레퍼런스가 되고 있었다. 이번엔 본인이 직접 공식 플러그인으로 출품한 셈이다.

10초 시작법

# 1. Cursor에서 플러그인 설치
/add-plugin pstack

# 2. 설정: 추론 예산(reasoning budget) 선택 + 모델 선택
/setup-pstack

# 3. 실제 작업: 프롬프트 앞에 붙이기
/poteto-mode 이 버그를 수정해줘

# 어떤 스킬을 쓸지 모르면?
/poteto-help

동작 방식: 23개 플레이북 + 멀티모델 분배

/poteto-mode는 23개의 플레이북(playbook)을 내장한다. 각각이 "이런 작업은 이렇게 접근하라"는 엄격한 절차다:

  • investigation — 읽기 전용 질문(코드베이스를 바꾸지 않고 탐구)
  • bug fix — 재현 → 근본원인 → 런타임 증거로 수정
  • perf — 베이스라인 대비 개선 측정
  • hillclimb — 지표별 과학적 반복 개선
  • …외 19개

또 하나 흥미로운 건 기본 멀티모델 패널이다. pstack은 기본적으로 두 모델을 역할 분담한다:

  • grok — 코드 위임 작업 (기능 구현·리팩토링·버그 수정·성능 개선)
  • opus 5.5 — 판단이 필요한 작업 (가장 어려운 변경·문서 작성·최종 판단)

개발자 관점 포인트: "비싼 모델을 항상 쓰는 게 아니라 작업 난이도별 모델 라우팅"이라는 점. 이건 우리도 바로 적용할 수 있는 실전 패턴이다 — 에이전트에게 단순 구현은 저비용 모델에게, 아키텍처 판단은 최상위 모델에게.

핵심 원칙: "추측으로 코드를 고치지 않는다"

대표 플레이북인 bug fix의 4단계 절차는 에이전트 워크플로우의 검증 게이트를 설계할 때 그대로 베껴 쓸 수 있다:

  1. 재현 — 버그를 먼저 재현한다 (추측 수정 금지)
  2. 근본원인 — 원인을 끝까지 파고든다
  3. 런타임 증거로 수정 — 증거 기반으로만 고친다
  4. 검증 — 테스트로 증명한다

AX TF 실무 관점에서 이 흐름의 의미는 분명하다: 에이전트 코딩의 병목이 "속도"에서 "품질·검증"으로 넘어가고 있다는 것. pstack은 그 전환의 대표 사례다.

아직 미확인: cursor/plugins 레포 전체 스타(11,692)와 달리 pstack 개별 다운로드 수는 미확인. "write less, but higher quality" 주장에 대한 독립 검증도 없다. 레퍼런스 스킬로 참고하되 효과는 직접 측정할 것.
