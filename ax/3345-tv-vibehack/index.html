2026-10-22 · AX 트렌드 · 원문 이슈 #3345

GitHub 레포 Gathin23/tv-vibehack이 2026-10-17에 공개된 뒤 약 1.5일 만에 1,900+ 스타를 받았다 (GitHub API 기준 created 2026-10-17T08:12:35Z). 컨셉은 한 줄이다.

"Your TV, minus the ads." — Wi-Fi로 Android TV·Google TV의 블로트웨어를 걷어내고, 광고 가득한 홈 화면을 tvOS풍의 깔끔한 런처로 교체한다. 루트 불필요, 케이블 불필요, 아무것도 삭제하지 않고, 한 줄로 복원된다.

계기는 개인 사연이다. "It started as an afternoon fixing my parents' Mi TV, which showed them an advert before they could reach Netflix." — 부모님 Mi TV가 넷플릭스에 닿기 전에 광고를 먼저 보여줘서 고치던 오후 프로젝트였다.

동작 방식 3단계

  1. 백업 — 설치된 패키지·설정 목록을 먼저 스냅샷으로 남긴다.
  2. pm disable-user — 제조사의 텔레메트리·광고 서비스·콘텐츠 행·선탑재 정크를 비활성화한다. 핵심 안전장치는 이것이다: "Nothing is uninstalled, so a restore script can undo every step." 삭제가 아니라 비활성화라 복원 스크립트로 전부 되돌릴 수 있다.
  3. tvOS풍 네이티브 런처 설치 — 작은 네이티브 런처를 설치해 기본 홈 화면으로 지정한다.

필요 조건은 TV와 같은 Wi-Fi에 있는 컴퓨터, 개발자 옵션→USB 디버깅을 켠 TV, 그리고 셸에 접근 가능한 코딩 어시스턴트(Claude Code 등)다. 이 프로젝트의 진짜 포인트는 레포의 PROMPT.md에 실제 쓴 프롬프트가 들어 있다는 점이다. 그대로 붙여넣으면 재현된다.

알아둘 점

  • 브랜드별 블로트 상이 — 블로트가 브랜드마다 달라서 프롬프트가 어시스턴트에게 TV를 직접 탐색하고 건드리기 전 확인하게 만든다. 테스트된 TV 목록·실패 케이스는 레포 이슈로 확인할 일이다.
  • 개인 프로젝트 — 동봉 런처의 완성도·유지보수 주체는 미확인이다.
  • 업데이트 후 동작 미확인 — pm disable-user가 시스템 업데이트 후에도 유지되는지 등 장기 동작은 미확인이다.
⚠️ ADB로 TV 건드리기 전 확인. ADB는 폰과 같은 디버그 브리지라 TV도 Wi-Fi로 리슨한다. 조작은 비활성화 위주지만, 제조사 앱 중 의존성이 있는 항목을 끄면 기본 기능이 멈출 수 있다. 백업→프롬프트의 확인 단계→한 항목씩 순서를 지킨다.

왜 중요한지

Android 개발자에게는 익숙한 ADB를 TV에 적용한 사례다. AX TF 관점에서 보면 이 프로젝트는 "코딩 에이전트가 실제 하드웨어와 대화하며 작업을 끝낸" 바이브코딩 패턴의 교본이다. 어시스턴트가 셸을 통해 실기기를 탐색하고, 브랜드별 차이를 확인하고, 건드리기 전 묻는다.

같은 패턴(어시스턴트 + 셸 + 실기기 탐색)은 사내 디바이스 자동화·테스트 팜 운영에 그대로 응용된다. PROMPT.md가 통째로 공개돼 있다는 점에서, 바로 써먹을 수 있는 재료다.
