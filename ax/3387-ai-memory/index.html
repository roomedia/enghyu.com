GitHub · ax-trend 이슈 #3387 · 2026-10-21 푸시 · 12,188★ · MIT · Rust

핵심 — 에이전트를 바꿔도 설명을 다시 하지 않는다

  • ai-memory는 AI 코딩 에이전트용 장기 메모리 서버다. README의 문장 그대로, "Quit Claude Code mid-task, start OpenAI Codex in the same directory, continue without re-explaining" — 작업 도중에 에이전트를 바꿔도 다시 설명하지 않고 이어서 작업할 수 있게 한다.
  • Claude Code·Codex·Cursor·Gemini CLI·OpenCode·Grok·Devin·Kimi·Kiro 등 20개가 넘는 하네스가 하나의 공유 메모리에 연결된다.
  • 기본 경로는 LLM 호출이 0이다. 캡처·검색·핸드오프가 API 키 없이 동작한다.
  • 메모리의 정본은 평범한 마크다운 파일들의 git 백업 위키다. grep·Obsidian·손 편집·rsync가 그대로 통하고, 벡터 스토어가 없으며, 데이터베이스는 파일에서 언제든 다시 만들 수 있는 파생 인덱스다.

핸드오프 — 세션을 통째로 넘긴다

  • ai-memory run으로 세션을 에이전트 간에 통째로 넘길 수 있다. Claude Code를 종료하고 ai-memory run codex를 실행하면, Codex가 공유 워크스트림과 Claude의 로컬 히스토리를 받아 이어서 작업한다.
  • 핸드오프는 소유자(owner)가 있고 정확히 한 번만 청구되는 타입드 프로토콜이다. 두 에이전트가 같은 작업을 중복으로 집어가는 일을 구조적으로 막는 설계다.
  • 서버가 받는 것은 하네스·세션 식별자뿐이다. 로컬 트랜스크립트 경로나 본문은 절대 전송되지 않는다.
# Claude Code에서 하던 작업을 Codex로 넘기는 흐름 (README 기준)
ai-memory run codex
여러 에이전트를 번갈아 쓰는 실무자에게 메모리 자체보다 중요한 것은 "어떤 에이전트에서든 이어지는" 핸드오프다. ai-memory는 그 지점을 제품의 정면으로 내세운다.

git 위키와 프라이버시 경계 — 파일이 정본이다

  • 팀 단위 사용이 기본 설계에 포함돼 있다. 한 서버에 여러 명이 연결하면, 한 사람의 세션에서 학습한 내용을 모두의 에이전트가 검색할 수 있다. 멀티유저 인증·개인별 귀속·감사 로그가 유료 티어가 아닌 기본 기능이다.
  • 라이프사이클 훅이 프롬프트·툴 호출·세션 경계를 기록할 때, 타입드 프라이버시 경계에서 살균한 뒤 저장한다. 민감한 내용이 그대로 메모리에 남지 않게 거르는 층이 있다는 뜻이다.
  • 메모리가 파일이면 감사·백업·수동 개입이 쉽다. 에이전트 메모리를 블랙박스 서비스에 맡기지 않고, 평소 쓰던 도구로 열어보고 고칠 수 있다는 점이 실무적으로 크다.

노화하는 메모리 — LLM 없이 감쇠·압축·병합한다

  • LLM 없이 메모리가 노화한다. 티어별 감쇠 스케줄을 조정할 수 있고, 자주 쓰는 메모리는 감쇠가 느려진다.
  • 식은 에피소드는 내구성 팩트(파일 경로·에러 코드·결정)로 압축되고, 유사 중복은 병합되며, 모순 가능성이 있으면 플래그가 붙는다.
  • 삭제는 없고, 원본은 git에 남는다. 메모리가 "사라지는" 방식이 아니라 "가라앉고 압축되는" 방식이다.

배경 — 메모리 레이어 경쟁, 차별점은 조합이다

에이전트 메모리 레이어 경쟁이 붙었다. 텐센트 Hy Memory 2.0(관련 이슈 #3332, 10/16), rohithhn Agentic Brain(관련 이슈 #3343, 10/18), Asymptote Labs Beacon(관련 이슈 #3384, 10/21)이 같은 주를 달린다. ai-memory의 차별점은 벤더 중립 + LLM 0콜 + git 네이티브라는 조합이다. 어느 하나만으로는 흔하지만, 세 가지가 함께 붙은 제품은 드물다.

왜 중요한지 — AX TF 실무에 바로 꽂히는 인프라다

코딩 에이전트를 여럿 쓰는 AX TF 실무에 바로 꽂을 수 있는 인프라다. API 키 없이 LLM 호출 0으로 동작하므로 비용 부담이 없고, 메모리가 git 위키라 감사·백업·수동 개입이 쉽다. Claude Code에서 하던 작업을 Codex로 넘기는 "에이전트 간 이직" 시나리오가 현실화되는 도구라는 점에서, 코딩 에이전트 워크플로우의 표준 부품 후보가 될 수 있다.

아직 안 밝혀진 것 / 쟁점

  • 핸드오프 품질·기억 유지율에 대한 정량 벤치마크 미공개.
  • 다중 사용자 환경의 보안 모델(서버 측 접근 제어) 세부 사항 미확인.
  • aimemory.sh 웹사이트의 추가 정보와 Windows 지원 여부 미확인.
  • 메모리 품질이 LLM 기반 메모리 시스템(전용 메모리 라이터 모델)과 비교해 어느 수준인지 미검증.
