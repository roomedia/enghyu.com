핵심 — 파일 이름이 아니라 내용을 말하면 찾는다

  • ARahim3/DigUp은 'Describe it. Dig it up.' — 컴퓨터에 있는 파일을 내용의 의미로 검색하는 오픈소스 데스크톱 앱이다. 2026년 10월 8일 레포 생성, MIT 라이선스 (GitHub).
  • 사용 방식: 어떤 앱에서든 단축키(⇧⌘Space on Mac, Ctrl+Shift+Space on Win/Linux)로 검색 패널을 띄우고 자연어로 설명하면, 파일 종류와 무관하게 매칭된다 (README).
  • 개념적으로 이 쿼리가 이 결과를 낸다 (README 설명 기준, 개념 예시):

  • 파일명을 기억할 필요가 없다. 의미를 설명하면 파일이 찾아온다 (이슈 배경).

엔진 — EmbeddingGemma 2: 텍스트·이미지·오디오·비디오가 하나의 공간에

  • Google DeepMind가 2026년 10월에 릴리스한 멀티모달 임베딩 모델 EmbeddingGemma 2가 엔진이다. 740M 파라미터, Apache 2.0 오픈, 100개 이상 언어 지원. 텍스트·이미지·오디오·비디오를 하나의 공유 임베딩 공간에 넣는다 (README).
  • 865MB 모델을 최초 1회만 다운로드하고, 이후엔 전부 온디바이스로 동작한다 (README). GPU 없이 CPU로도 돌아가게 설계된 경량 멀티모달 모델이라 가능한 구조다.
  • 읽는 범위: 사진·스크린샷(보이는 내용 기준, Mac에서는 스크린샷 안의 텍스트도), PDF(페이지 단위, 최대 5,000페이지), 문서(txt·md·rtf·docx·odt·html), 오디오(30초 겹침 윈도우로 구간 지정), 비디오(샷당 프레임 + 사운드트랙) (README).
  • 의미 검색과 함께 정확한 문자열(송장 번호·에러 코드·이름)도 파일명·문서 텍스트에서 그대로 매칭한다. 영어 질의로 벵골어·아랍어 메모를 찾는 식의 교차 언어 검색도 된다 (README).

프라이버시 — 아무것도 컴퓨터를 떠나지 않는다

  • 인덱싱 데이터가 컴퓨터를 떠나지 않고, 텔레메트리·계정이 없다 (README). 클라우드에 올리는 게 없어서 유료 API 비용도, 데이터 유출 걱정도 구조적으로 제거된다.
  • 코드 검색은 옵트인이다. 코드 프로젝트 폴더(.git·package.json 등)에서는 스크린샷만 읽고, 키·인증서·비밀번호 파일·.ssh·앱·캐시는 절대 읽지 않는다. 클라우드에만 있는 파일(iCloud·OneDrive)도 내려받지 않는다 (README).
  • 검색 품질과 프라이버시를 둘 다 잡는 방식은 읽지 않을 것을 명시적으로 제외하는 것이다. 온디바이스라는 말이 광고 문구가 아니라, 접근 금지 리스트까지 코드에 박혀 있다 (이슈 배경).

견인력 — 생성 2주 만에 5천 스타

  • Mac·Windows·Linux를 지원한다. Mac은 정식 릴리스(DMG·Homebrew cask), Windows/Linux는 v0.7.0-beta.2다 (README).
  • 2026년 10월 21일 기준 스타 5,295·포크 392, 최근 푸시는 10월 18일. 하루 약 400스타 페이스로 성장 중이다 (GitHub).
  • EmbeddingGemma 2가 10월 중순 공개된 직후 나온 생태계 첫 실용 앱 중 하나다. OS 차원의 AI 파일 검색(Windows Recall, macOS 스포트라이트의 의미 검색 확장)과 같은 방향을 오픈소스·크로스플랫폼으로 구현한 사례다. 생성 2주 만에 5천 스타를 넘기며 온디바이스 AI에 대한 개발자 수요를 보여준다 (이슈 배경).
AX TF 관점. 이 앱 자체보다 참고 가치가 큰 건 온디바이스 임베딩의 실전 레퍼런스 구현이라는 점이다. 개발자 개인 지식 베이스(프로젝트 코드·문서·회의 녹취·레퍼런스 이미지)를 클라우드 없이 로컬에서 의미 검색하는 워크플로우를 바로 써볼 수 있다. Android 개발자 관점에서는 EmbeddingGemma 2(740M, Apache 2.0) 자체가 온디바이스 시맨틱 검색의 유력한 백본 후보라서, 이 앱의 인덱싱·청킹(오디오 30초 윈도우, 비디오 샷 단위 프레임) 방식을 모바일 앱 설계에 참고할 만하다 (이슈 배경).

아직 안 밝혀진 것 — 모바일 버전·한국어 검색 품질·Windows 서명

⚠️ 미확인: 모바일(Android/iOS) 버전은 없다 — 데스크톱 전용이라 폰 파일 검색에는 못 쓴다 (README). 한국어 질의·한글 문서의 검색 품질은 README 예시에 없어 미확인이다 (예시는 영어·벵골어·아랍어). Windows 설치 프로그램이 아직 서명되지 않아 설치 시 '알 수 없는 앱' 경고가 뜬다 (README).

배경 — 온디바이스 AI 파일 검색의 수요는 이미 증명됐다

OS 제조사들이 AI 파일 검색에 베팅하는 이유가 DigUp의 스타 곡선에 그대로 보인다. 사용자는 자기 파일을 클라우드에 올리고 싶어 하지 않는다. 이 앱은 멀티모달 임베딩 모델이 가벼워지면(740M) 데스크톱 의미 검색이 실용해진다는 걸 실증한 첫 케이스다. 같은 아키텍처를 모바일 개인 지식 베이스로 가져오면, 기기 안의 모든 콘텐츠가 검색 가능한 개인 메모리가 된다 (이슈 배경).

실무 체크리스트

  • 온디바이스 시맨틱 검색 백본 후보로 EmbeddingGemma 2를 평가한다. 740M·Apache 2.0·100+ 언어 — 모바일 탑재 가능한 무게다 (README).
  • 인덱싱 청킹 방식을 벤치마크한다. 오디오 30초 겹침 윈도우, 비디오 샷 단위 프레임 + 사운드트랙 — 미디어 검색의 정답지 격이다 (README).
  • 접근 금지 리스트를 명세에 넣는다. 키·인증서·.ssh·클라우드 파일 제외가 프라이버시 신뢰의 핵심이다 (README).
