Shanghai AI Lab 'Atria Dawn' 정식 버전 — 744B MoE 에이전트 모델, MIT 라이선스로 등장

2026-10-21 · AX 트렌드 · 원문 이슈 #3342

Shanghai Artificial Intelligence Laboratory(상하이 인공지능 연구원)가 에이전트 모델 Atria Dawn의 정식 버전(full release)을 공개했다. 연구·소프트웨어 개발·다단계(multi-step) 작업을 겨냥한 모델로, 7440억(744B) 파라미터 mixture-of-experts 구조를 갖춘 Zhipu의 GLM-5.2 기반 에이전트용 포스트트레이닝 모델이다. 코드가 MIT 라이선스로 공개된다는 점이 가장 큰 포인트다.

9월 프리뷰(9/11 가중치 등장, 9/14 arXiv 보고서, 9/15 정식 발표) 이후 약 한 달 만의 후속 릴리스로, 벤치마크 개선과 새 데모를 앞세웠다. 베이스인 GLM-5.2는 Zhipu가 6월에 MIT 라이선스로 공개한 744B 코딩·도구 활용 파운데이션 모델이다.

벤치마크: 대부분 상승, BrowseComp는 하락

벤치마크정식프리뷰변동
JobBench57.550.3+7.2
WideSearch84.681.9+2.7
PaperBench89.687.0+2.6
SWE-bench Pro61.759.6+2.1
BrowseComp91.392.5-1.2

JobBench의 +7.2점 상승이 눈에 띈다. 반면 BrowseComp는 91.3으로 프리뷰(92.5)보다 소폭 하락했다. 모두 연구실 자체 측정치이므로 하락 원인은 설명되지 않았다. 발표 수치 그대로 믿기보다 실측이 필요하다.

쟁점: 512K vs 256K, 그리고 'Coming soon' 가중치

⚠️ 컨텍스트 윈도우 표기 불일치. 연구실 발표에 따르면 컨텍스트가 256K에서 512K 토큰으로 늘었다. 그러나 GitHub 다운로드 표에는 정식 모델과 FP8 버전 모두 여전히 256K로 표기되어 있다. 어느 쪽이 실제 서빙 기준인지 미확인 상태다.

더 근본적인 문제는 정식 버전의 가중치가 Hugging Face·ModelScope에서 'Coming soon' 상태라는 점이다. 지금 다운로드 가능한 것은 프리뷰 가중치뿐이다. 즉 발표된 모델, 호스티드 서비스, 다운로드 체크포인트는 서로 다른 것이다. 자체 호스팅·파인튜닝은 아직 불가하고, 호스티드 API(국제용·중국용 엔드포인트 분리)로만 쓸 수 있다. API 가격도 미공개다.

텍스트 입력 전용. "accepts text input only" — 이미지나 오디오 입력은 받지 않는다. 비주얼 리즈닝(Elorian Glimpse 같은) 워크로드에는 맞지 않는다.

데모: 다단계 작업 위주 쇼케이스

공식 릴리스 쇼케이스의 데모는 "대화형 답변을 넘는" 다단계 작업 위주다:

  • CAD 모델링 — 도구를 직접 다루는 설계 작업
  • 프레젠테이션 생성 — 네이티브 PowerPoint 요소 + Morph 전환으로 29장 애니메이션 시퀀스
  • 데이터 분석 — 5개 업무 파일을 가로질러 대사(대조)·실적 분석

29장 슬라이드를 Morph 전환까지 넣어 만든다는 건 단순 텍스트 생성이 아니라 문서 구조를 이해하고 도구를 연속 호출한다는 의미다. 에이전트 워크로드 평가 후보로 넣어볼 만한 이유다.

개발자 관점: 지금 당장 해볼 수 있는 것

MIT 라이선스의 744B급 오픈 에이전트 모델이라는 점에서 AX TF의 에이전트 워크로드 평가 후보가 된다. 호스티드 API가 OpenAI 호환이라면 기존 에이전트 스택에서 엔드포인트만 바꿔 시험해볼 수 있다:

import openai
client = openai.OpenAI(
    base_url="https://api.atria-dawn.example/v1",  # 실제 호스티드 엔드포인트로 교체
    api_key="<YOUR_KEY>",
)
resp = client.chat.completions.create(
    model="atria-dawn",
    messages=[{"role": "user", "content": "이 레포의 CI 실패 원인을 분석하고 수정 PR을 만들어줘"}],
)
⚠️ 도입 전 확인 항목. ① 512K/256K 어느 쪽이 실제 서빙 기준인지 ② 정식 가중치 공개 시점(재현·자체 서빙·파인튜닝 가능 여부) ③ BrowseComp 하락 원인 ④ 호스티드 API 가격. 특히 텍스트 입력 전용이라는 제약과 정식 가중치 미공개는 도입 검토 시 감안해야 한다.

발표 수치 그대로 믿지 말고 실측하라는 교훈을 다시 주는 릴리스다. 컨텍스트 표기 불일치 같은 디테일 하나가 배포 판단 전체를 흔든다.
