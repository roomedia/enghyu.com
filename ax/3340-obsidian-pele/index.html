Obsidian, 오픈소스 Mermaid 렌더러 'Pele' 공개 — Mermaid.js 대비 번들 1/6·최대 500배 빠른 렌더 주장, CSS 변수 테마 지원

2026-10-21 · 원문 이슈 #3340 · 소스: Hacker News (10/17)

Mermaid.js는 "다이어그램을 텍스트로 쓰는" 표준이 됐다. 그런데 그 무게도 표준이 됐다: gzip 번들 1.6MB, 렌더 6–82ms. 10월 17일 Hacker News 프론트페이지에 오른 Obsidian의 오픈소스 라이브러리 Pele은 이 숫자를 정면으로 공략한다. Mermaid 문법을 그대로 받아 SVG로 렌더하는 드롭인 대체품이다:

npm install pele

import { render } from "pele";
const svg = render("flowchart TD\n  A[시작] --> B{테마?}\n  B -->|다크| C[용암 모드]");
document.body.innerHTML = svg;

공식 사이트(pele.run)가 밝힌 Mermaid.js 대비 수치:

Mermaid.jsPele
gzip 번들1.6 MB230 kB (약 1/6)
렌더 시간6–82 ms0.05–0.3 ms (최대 500배)
직접 의존성23개0개

0.05ms의 의미: LLM이 그림을 대량으로 그리는 시대

82ms → 0.05ms가 왜 중요하냐면, LLM이 다이어그램을 대량 생성하는 시대에 렌더링이 병목이 되기 때문이다. 문서·테크블로그·챗봇 응답에 플로우차트가 수십 개씩 들어가는 파이프라인에서는 6–82ms × N이 그대로 체감 지연이다. Pele는 여기서 리렌더 비용 자체를 날려버리는 전략을 쓴다 — 아래 테마 기능과 이어진다.

CSS 변수 테마: 리렌더 없이 색상만 바꾼다

Pele의 개발자 경험상 킬러 기능은 속도보다 이쪽일 수 있다. --pele-bg·--pele-fg·--pele-line 같은 CSS 변수로 배경·전경·선·표면·보더 색상과 폰트를 지정하면, 색상 변경이 리렌더 없이 즉시 반영된다. 다크모드 토글 버튼 하나로 문서 뷰어 전체의 다이어그램 테마가 바뀌는 것. 작은 화면에서는 다이어그램을 무작정 스케일링하는 대신 레이아웃을 자동 적응시킨다. Obsidian이 자체 노트 앱의 "빠른 렌더 + 테마 매칭" 필요로 직접 만든 뒤 공개한 이유가 드러나는 대목이다.

지원 범위는 Mermaid 12.1.0에 내장된 모든 다이어그램 타입을 명시한다.

생태계: 공개 24시간 만에 스킬·CLI·플러그인 4종

HN 게시(dchest, 2026-10-17 15:55 UTC)는 561포인트로 프론트페이지에 진입했다. GitHub 레포(obsidianmd/pele, 10/5 생성)는 현재 스타 1,721개. 흥미로운 건 속도보다 생태계 형성 속도다. 공개 다음 날인 10/18 하루에만:

  • jpmanson/pele-skill — 코딩 에이전트용 스킬
  • ahmedelgabri/pele-cli — CLI
  • farnabaz/streamdown-pele, farnabaz/comark-pele — 마크다운 렌더러 통합

특히 에이전트 스킬이 공개 당일에 나왔다는 게 포인트다. LLM이 문서를 자동 생성하는 파이프라인에서 "Mermaid 텍스트를 뽑아 렌더"하는 부분은 지금도 흔한 워크플로인데, Pele는 그 슬롯에 번들 부담 없이 꽂힌다.

AX TF 관점: 기술 문서·공유 자료에 LLM이 생성한 Mermaid 다이어그램을 넣을 때 렌더링 속도와 다크모드 테마 매칭이 바로 걸림돌이다. Pele는 리렌더 없는 CSS 변수 테마 전환과 0 의존성으로 웹/앱 문서 뷰어에 붙이기 쉽고, 에이전트 스킬까지 나온 만큼 문서 자동 생성 파이프라인(마크다운→다이어그램→테마 적용)에도 바로 응용할 수 있다. 다크모드 토글 한 번으로 전체 다이어그램이 뒤바뀌는 데모는 임팩트가 확실하다.

주의 (미확인·쟁점): 230 kB·0.05–0.3 ms·500배 같은 성능 수치는 프로젝트 자체 제공 비교로, 벤치마크 조건·독립 검증이 없다. 공식 사이트는 "open source"라고만 표기하고 GitHub 라이선스 필드는 other(비표준)로 표시되니 구체 라이선스 미확인. "Mermaid 12.1.0의 모든 타입 지원"이 엣지 케이스까지 완전 호환인지도 사용자 검증이 필요하다.

배경·맥락

Mermaid.js가 사실상 표준이 된 건 "텍스트→다이어그램"이라는 문법의 승리였다. 하지만 웹 앱에서 1.6MB 번들과 6–82ms 렌더는 부담이었고, 특히 LLM이 다이어그램을 대량 생성하는 흐름에서 렌더링이 병목이 되기 쉬웠다. Obsidian은 자체 노트 앱에서 빠른 렌더링과 테마 매칭이 필요해서 직접 만든 뒤 공개한 것. 라이브러리 하나가 해결하는 문제가 "우리 제품의 진짜 병목"에서 나왔을 때 폭발적이라는, Obsidian다운 공개다.
