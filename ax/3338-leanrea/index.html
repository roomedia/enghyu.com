왜 MCP가 문제인가 — 설계 철학

REA는 강력하다. 하지만 그 강력함의 대가는 매 요청마다 207개 도구의 정의(3.35MB)를 컨텍스트에 실어 보내는 것이다. leanrea의 주장은 단순하다: "에이전트가 이미 쓸 수 있는 CLI 도구로 충분하다."

MCP 서버는 에이전트와 실제 도구 사이에 한 겹의 추상화를 더한다. 그 추상화가 편리함을 주지만, 매 턴마다 수백 킬로토큰의 도구 정의를 운반해야 한다는 세금을 매긴다. leanrea는 이 세금을 걷어내고, 대신 에이전트에게 "이 바이너리 타입이면 이 명령부터 쳐라"라는 플레이북만 SKILL.md에 적어준다. 인프라가 아니라 지시문으로 능력을 전달하는 것이다.

구조적으로 보면: REA는 "도구를 미리 등록해서 에이전트가 호출하게" 하는 방식이고, leanrea는 "에이전트가 직접 터미널을 두드리게" 하는 방식이다. 전자는 설정·유지보수·컨텍스트 비용이 크고, 후자는 에이전트의 자율성(실패 시 다른 명령으로 재시도)에 의존한다. 둘 중 어느 쪽이 '에이전트 시대'에 맞는 설계인지는 팀마다 다르게 답할 수 있지만, 수치상 후자의 효율은 부정하기 어렵다.

실무 패턴 — 에이전트가 실제로 치는 명령

leanrea의 스킬 파일이 에이전트에게 지시하는 건 이런 흐름이다. 바이너리 종류를 파악한 뒤, 그에 맞는 가장 빠른 원시 명령을 선택한다:

# Electron 앱: asar 아카이브 먼저 확인
$ npx asar list app.asar | head -20

# Go 바이너리: 내장 모듈 정보 추출
$ go version -m ./target-binary

# macOS 네이티브: 심볼 테이블 확인
$ otool -L ./target && nm -gU ./target | head -30

# Android APK: 리소스 디코드 + dex→java
$ apktool d app.apk && jadx -d out app.apk/classes.dex

# 펌웨어: 시그니처 스캔 후 추출
$ binwalk firmware.bin && binwalk -e firmware.bin

# 앱 데이터: sqlite 직접 쿼리
$ sqlite3 data.db "SELECT * FROM meta LIMIT 5;"

Android 개발자 관점에서 이 패턴은 낯설지 않다. apktool·jadx로 서드파티 SDK나 레거시 APK를 분석할 때, Claude Code/Codex에 이 명령들을 직접 시키면 된다는 뜻이다. MCP 플러그인을 설치·유지할 필요 없이 스킬 파일 하나로 팀 전체가 같은 플레이북을 공유할 수 있다.

주의 (미확인·쟁점): 벤치마크는 저자 본인이 설계·실행한 셀프 리포트다. 정답지가 수제이고 태스크가 macOS arm64(Mach-O·Electron) 중심이라 다른 OS·태스크에서의 재현성은 미확인. leanrea는 74/75점으로 REA(75/75)보다 근소하게 낮다 — 유일한 부분 실패는 "오래된 IPC 채널을 명명한 것(두 채널 모두 존재)". 수치를 인용하기 전 레포의 bench/ 디렉터리 caveat를 함께 확인할 것. Claude Code·Codex 외 에이전트(Gemini CLI, Copilot CLI 등) 호환성은 언급 없음.

배경·맥락

morluto/rea(#3141)는 10/8 GitHub 일간 트렌딩에 진입하며 약 19.7K 스타를 모은 에이전트용 리버스엔지니어링 스킬이다. 이후 rea-agents(#3204), REA 클린룸 워크플로우(#3322)까지 이어지며 REA 에코시스템이 형성됐다. leanrea는 이 흐름에 대한 반작용 성격의 경량 대체품이다. MCP 서버와 207개 도구 정의가 컨텍스트·비용에 주는 부담을 문제 삼고, 에이전트 스킬 경량화 트렌드의 대표 사례로 읽힌다.

AX TF 관점: 'MCP 없는 에이전트 스킬'이라는 설계 패턴 자체가 참고할 만하다. MCP 서버 설치·유지 부담 없이 SKILL.md 하나로 에이전트 능력을 확장하는 방식은 권한·설치 제약이 큰 사내 환경에도 바로 응용 가능하다. 특히 "도구 정의를 컨텍스트에 싣는 게 비싸다"는 통찰은 모든 에이전트 스킬 설계에 적용할 수 있다 — 도구는 적게, 지시문은 구체적으로.
